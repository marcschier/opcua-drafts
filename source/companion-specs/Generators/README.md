# OPC UA for Generators

`OPC 99007-1` — the placeholder number; see [DOCUMENT-NUMBERS.md](../../../DOCUMENT-NUMBERS.md).

This specification is built by `Opc.Ua.SpecificationPublisher` from the markdown here and the
UANodeSet in `model/`. The prose is split the way `AUTHORING.md` describes: `spec.md` holds the
clauses a reader moves through, `object-types.md` and `data-types.md` hold the two clauses that
are most of the document and are read in by `{include}` directives.

Clause 2, clause 3, the Namespaces clause, the Profiles clause, Annex A and Annex B are
**generated** — from `manifest.json`, `profiles.json` and the NodeSet. Do not write them here.

```powershell
dotnet Opc.Ua.SpecificationPublisher build --spec Generators
dotnet Opc.Ua.SpecificationPublisher publish
```

## The model

`model/Opc.Ua.Generators.NodeSet2.xml` and `model/Opc.Ua.Generators.NodeIds.csv` are generated by
`tools/build_model.py`, which is the single source of truth for both. Never edit either file.

```powershell
python source/companion-specs/Generators/tools/build_model.py
```

The node-definition tables in `object-types.md` and `data-types.md` are **authored**, because the
publisher has no directive that generates one — `defines=` on a caption binds a table to the type
it documents and the build reports where the two disagree. They were first emitted from the
NodeSet by `word-drafts/tools/emit_node_tables.py`; from here on they are edited by hand and the
build keeps them honest:

```
55 definition table(s) bound, 0 differ from the model
```

The field table under each DataType is bound with `datatype=` instead, and *is* generated:
`update --write` fills it from the `DataTypeDefinition` and keeps it in step. Its caption is
written with no table under it on purpose.

## A known build failure

**The build currently fails, and the cause is in the publisher rather than in this
specification.**

```
error: Unknown namespace(s) referenced: Node 'nsu=http://opcfoundation.org/UA/Machinery/;i=5050'
TypeId references unknown namespace 'http://opcfoundation.org/UA/IA/'
```

This model requires OPC 40001-1, which borrows one Object, `Stacklight`, from OPC 40080-1. The
publisher does not register a namespace it reaches only through a dependency, so it cannot resolve
that Object even though the file defining it is present.

`model/dependencies/` holds the exactly consistent set: DI 1.04.0, Machinery 1.04.1 and IA 1.01.2,
each the version the one above it declares. Five explanations were tested and eliminated — a
missing file, a version mismatch, a namespace absent from the manifest table, an undeclared
`RequiredModel`, and an inconsistent dependency set. Removing the two `Stacklight` Nodes from a
local copy of Machinery builds the specification cleanly, which is what identifies the cause.

The requirement on OPC 40001-1 is correct and stays as it is: changing the model to avoid a
defect in a tool would leave the model wrong once the tool is fixed.
